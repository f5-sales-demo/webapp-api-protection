The demo runs nine applications on an Azure origin VM, with a separate traffic-generator VM
and F5 Distributed Cloud protection. The existing www and api endpoints share the origin with
five simultaneous HTTPS comparisons under f5-sales-demo.com.

| Comparison | Baseline host | Protected host |
| --- | --- | --- |
| Web application firewall | waf-before | waf-after |
| Request schema | schema-before | schema-after |
| Endpoint methods | endpoint-before | endpoint-after |
| Per-user rate limit | rate-before | rate-after |
| Malicious-user detection | mud-before | mud-after |

Walkthroughs read the private Terraform `use_cases` output and exercise both endpoints.
They do not change protection configuration. Each comparison has isolated policy and synthetic
user identities. Background attack traffic excludes baseline hosts. Client-Side Defense remains
display-only.

## Operation

Use the [Terraform ownership reference](../reference/terraform-ownership/) for saved plans,
reviewed adoption, immutable fixtures, guest verification, and the live acceptance gates.
The [Terraform operator guide](https://github.com/f5-sales-demo/webapp-api-protection/blob/main/terraform/README.md)
contains prerequisites and command details.

The lifecycle supports `plan`, `adopt`, `deploy`, `verify`, `rebuild`, and `destroy`.
Use the approved private operator configuration and the same Ubuntu state location across
worktrees. Saved plans bind source, inputs, provider locks, and state. Rebuild consumes a reviewed
plan and preserves the namespace, listeners, and shared prerequisites.

## Acceptance

Published comparison articles require live control attribution and successful legitimate requests,
all nine applications through native, proxy, and published routes, two complete 164-entry catalog
passes, and stop/start and reboot recovery. Catalog traffic must remain within five percent of
200 aggregate HTTP requests/second, with at least 99 percent benign success and zero baseline
transport failures.

A second unchanged apply and refreshed plan must contain zero resource and output actions after
walkthroughs, catalog testing, and reboot. Source checks, generic denied responses, and partial
catalog runs do not satisfy those gates. Deployment receipts remain private.
