F5 Distributed Cloud Web App and API Protection protects applications at the load balancer,
before requests reach the origin. This showcase gives sales engineers and customers a shared
way to inspect a request, enable a focused control and explain the resulting security event.
Terraform prepares the applications and protection resources. The use-case articles explain
what each protection changes for a caller.

## Start here

Read the [architecture and applications](./overview/) to choose an application and understand
the request path. [Prepare the showcase](./demo/) covers prerequisites, Terraform deployment
and cleanup. Open the demonstration window described in [evidence interpretation](./reference/evidence/)
before changing a control.

## Choose a protection

| Use case | Demonstration |
| --- | --- |
| [SQL injection and reflected cross-site scripting](./web-application-protection/injection-and-xss/) | Authenticated DVWA requests; monitoring to blocking |
| [Request validation](./api-protection/request-validation/) | A required JSON string; reporting to blocking |
| [Endpoint restrictions](./api-protection/endpoint-restrictions/) | Two methods on one path; allow to deny |
| [Rate limiting](./api-protection/rate-limiting/) | A bounded burst; disabled to 20 requests per minute |
| [Malicious-user mitigation](./behavior-based-protection/malicious-user-mitigation/) | A suspicious sequence followed by a benign request |

Each article follows the same sequence: risk, prerequisites, request, initial evidence,
configuration change, replay, legitimate request and restoration. Run categories sequentially.
HTTPBin illustrates policy behavior; DVWA supplies native synthetic vulnerability behavior.
Client-Side Defense remains display-only and has no mitigation walkthrough here.
